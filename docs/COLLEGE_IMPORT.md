# Обновление CRM на ПК: экспорт колледжа

## Что делать владельцу

1. Остановите старую CRM и сделайте резервную копию `crm.db`, `uploads/` и `.env`.
2. Обновите код в той же рабочей папке, сохранив эти файлы. Не используйте
   старый вложенный `CRM-main (1).zip`. Не создавайте новую пустую БД вместо рабочей.
3. Из корня CRM выполните `npm --prefix server ci --omit=dev`, затем `npm start`.
   Готовый интерфейс включён в `server/public`.
4. При наличии в корне `Экспорт_колледж - 20261029-184934.xlsx` CRM автоматически
   один раз импортирует этот файл в текущую базу от имени активного администратора.
   До импорта создаётся согласованный снимок `backups/before-college-*.db`.
   Настройки и пароли не сбрасываются. Итоги выводятся в консоли и истории импортов.
5. Откройте «Контакты» и «Календарь» / «ДОД». Мероприятия из этой книги имеют тип
   «Внешнее мероприятие» (фестиваль колледжей). Слой плана в календаре должен быть включён.

Чтобы запретить автоматический импорт, ДО запуска добавьте в `.env`:
`IMPORT_BUNDLED_COLLEGE=0`. Тогда книгу можно загрузить вручную через «Импорт».
Удаление файла после успешного импорта не удаляет людей из базы.

## Другие аналогичные таблицы

В разделе «Импорт» выберите `.xlsx`. Для книги с листами «Мероприятия» и «Заявки»
система выбирает лист с людьми, показывает его имя и количество строк.
Нажмите «Импортировать посещения» или нижнюю кнопку импорта: обе используют
специализированный обработчик колледжа. Телефон и почта организатора не подменяют
телефон и почту участника. Формат определяется по заголовкам, не по имени файла.

Распознаются ФИО, дата рождения, телефон, почта, школа, класс, регион и тип посетителя.
Прочие исходные колонки сохраняются в описании касания в виде JSON. Посещения и
регистрации относятся к отдельным событиям по названию, дате и времени, а не к
одному первому событию книги. Существующие непустые поля контакта не перезаписываются.

Повторные строки пропускаются по SHA-256 отпечатку. Для сопоставления людей
используются ФИО и нормализованный телефон с проверкой даты рождения;
GUID аккаунта или общий семейный телефон сами по себе не объединяют разных людей.
Это консервативное сопоставление: смена ФИО/телефона может потребовать ручного
разбора карточек. Файл содержит 851 заявку, не 851 уникального человека.

В тестовой пустой базе получено: **790 карточек, 14 мероприятий, 367 посещений,
484 регистрации, 0 пропущенных строк**. 61 строка сопоставлена с уже созданными
в этом импорте карточками. В существующей базе число новых карточек может отличаться.
Повторный импорт той же книги не создаёт новых карточек и касаний.

## Выгрузка всей базы

Администратору (`*`) на странице «Контакты» доступна кнопка **«Вся база Excel»**.
Она выгружает все строки рабочих таблиц на отдельные листы, без фильтров страницы
и без ограничения обычного экспорта контактов. Включены личные задачи и события,
контакты, мероприятия, касания, справочники, история импортов, чат, связи и метаданные
документов. Файлы документов, пароли, хэши, сессии и служебные настройки не выгружаются.
Обычное право `export.run` НЕ даёт доступа к полному экспорту.

Excel — для просмотра/анализа, не файл восстановления. Для восстановления сохраняйте
SQLite, uploads и настройки. Логический JSON-бэкап дополнен календарём и новыми
таблицами импорта. Старые JSON-бэкапы новых данных не содержат.

Книга и выгрузка содержат персональные данные: не публикуйте их и не отправляйте
посторонним. Загрузка исходного файла в публичный GitHub уже раскрывает его содержимое;
удаление из последнего коммита не удаляет его из истории.

## Проверки

`npm run build`, `npm --prefix server test`.
Все 23 серверных теста прошли. Тесты используют временные базы, проверяют именно приложенную книгу, повторную
загрузку, семейные телефоны, выбор колонок, календарь и защищённую Excel-выгрузку.


Дополнительно выполнена проверка Chromium: открыты дашборд, контакты, воронка,
задачи, календарь, ДОД, импорт, дубли, аналитика, чат и настройки. Проверены
предпросмотр приложенной книги, повторный импорт через интерфейс, скачивание
полного XLSX, создание/открытие/редактирование события и виды календаря.
В этих сценариях не обнаружены ошибки API или необработанные ошибки страницы.
Повторный запуск сервера сохранил 790 контактов и 851 отпечаток, импорт не повторился.
Это функциональная smoke-проверка, не полный аудит безопасности или нагрузочный тест.
Существующие предупреждения npm audit для xlsx и зависимостей не устраняются
этим обновлением; загружайте таблицы только из доверенных источников.

## Отчёт ДОД

В обновление также включён автоматический однократный импорт файла
`Отчет ДОД - 29.10.2026 19-20-30.xlsx` из корня проекта. Он выбирает лист
«Заявки (билеты)», распознаёт «ФИО посетителя» и не импортирует сводные строки
или контакты организаторов как посетителей. Можно загрузить такой отчёт и
вручную через «Импорт». Для отключения автоматической загрузки ДО запуска
добавьте `IMPORT_BUNDLED_DOD=0` в `.env`.

Перед загрузкой создаётся `backups/before-dod-report-*.db`. Рабочая база,
учётные записи и пароли не заменяются. Повторная загрузка тех же строк
не дублирует карточки или касания. Совпадения сопоставляются с контактами,
включая ранее загруженный экспорт колледжа.

В отчёте 499 строк билетов на 6 мероприятий: 307 посещений, 192 неявки.
Неявка сохраняется заметкой с исходными данными, но не засчитывается как
посещение или регистрация. В тестовой базе после импорта колледжа дополнительно
создано 445 карточек, 54 строки сопоставлены с существующими. Число новых
карточек в вашей рабочей базе может отличаться. Все 26 серверных тестов прошли,
включая предпросмотр, импорт, повторную загрузку и регрессию прежнего импорта.

На вашем ПК данные появятся после обновления кода и запуска CRM с сохранённой
рабочей базой. Не заменяйте `crm.db` пустой или тестовой базой.
